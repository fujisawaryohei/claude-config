# 重なりの洗い出しのチェック項目（Phase 1）

並行させる前に、タスクの組ごとに全部見る。1 つでも重なれば、境界の約束かマージの順で解く。

| 観点 | 見ること | 解き方の例 |
|---|---|---|
| 同じファイル | 両方が変えるファイル。同じ関数の中か、別の場所か | 触る行を分けて指示する・後から入る方が rebase |
| **同じ設計書の節** | 「既知のリスクを対処済みに直す」と「追記する」が同じ節に当たっていないか。**見落としやすい** | 片方は案をステータスに置くだけにし、先のマージの後に書く |
| コードの依存 | 片方が作る関数・型を、もう片方が使うか | 名前と型を約束し、呼び出しは先のマージの後に足す |
| 生成物 | OpenAPI・型の生成・migration の番号・lockfile | 生成は 1 本に寄せる。migration は down_revision を後で付け替える |
| 共有リソース | ローカルのコンテナ・DB・ポート・キャッシュ・外部の dev 環境 | with-lock.sh で 1 本ずつ・ポートをずらす |
| 共有の素材 | テンプレート・テストのデータ・秘密値 | 置き場を 1 つにして共有の約束に書く |
| 計測の前提 | 片方の結果で、もう片方が要るかどうかが決まるか | 計測を先にして「判断待ち」で止める段を指示書に入れる |
| 後続の作業 | 今回の結果を前提にする次の作業（チケットの有無によらない） | 今回は始めない。マージの順の図に載せる |

## ブランチの形

- squash merge のリポジトリでは、ブランチを積まない（下がマージされると上のコミットが二重になり、rebase で毎回ぶつかる）
- 全部 origin の base から独立に切る。依存は「マージの順」と「後から足す 1 行」で表す
