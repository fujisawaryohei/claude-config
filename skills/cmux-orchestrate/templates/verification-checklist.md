# 動作確認リストの形（Phase 7・固定）

**この形で出す。見出しの順・欄は変えない。** 短く、手順は手を動かす順に。

```markdown
## <呼び名> <タスク ID> <要約> の動作確認リスト

**対応した内容:**
- <何を直したか・足したかを 1 行で>
- <ユーザーから見て何が変わるかを 1 行で>
- <確かめてほしい肝を 1 行で>（2〜4 行に収める）

**環境:** <URL やコマンド>（<どの worktree・ブランチのコードで起動したか>）

1. <開く・ログインする>
2. <操作する（画面の名前・ボタンの名前は画面の表記どおり）>
3. <待つ・見るもの>
4. <結果を見るコマンド（ログ・DB など）。ユーザーが打つものは `! <コマンド>` の形にする>
5. <出た結果で、次を確かめる>
   - [ ] <確かめること 1>
   - [ ] <確かめること 2>

<4 の結果を貼ってもらえれば、値が妥当かを一緒に見る旨を 1 行>
```

## 書き方の決まり

- 「対応した内容」は、コードの名前ではなく、何が変わったかで書く（関数名・クラス名は括弧に入れる程度）
- 「環境」には、起動したもの（URL・ポート）と、**どのタスクのコードで起動したか**（worktree・ブランチ）を必ず書く。取り違え（別の worktree のサーバを見てしまう）を防ぐため
- 確かめることは、OK / NG を見て決められる形にする（「問題ないこと」のような書き方をしない）
- 画面で確かめられないもの（ログ・DB）は、見るためのコマンドを手順に入れる
